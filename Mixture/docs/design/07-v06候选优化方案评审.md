# v0.6 候选优化方案评审：多 Agent 讨论稿

日期：2026-09-19。分析基线：`b4607e4`（codex optimize v5）。状态：**仅供评审，以下方案均未实施，不代表已经获得性能提升。**

本轮由三个独立 Agent 分别分析战斗防御、经济路径、任务与信息利用，主 Agent 复核原始规则、源码及既有回放，合并建议并进行新阵型的纯几何检查。本轮仅新增本评审文档和工程内的目录约束文档，不修改代码、测试、模拟器或提交包。所有写入限定在 `CoreGeek/Mixture/`；原始 `docs/` 和其他版本保持只读。

## 1. 建议优先选择什么

建议下一轮先处理三个有具体失败证据的问题：**移动连续争格、夜间出售阻塞采集、开拓者无意离开任务点**。随后优化救命券就位与防守动作选择。新阵型、SOP 加速、动态火箭落点值得做独立实验，不宜一次全部替换。

| 编号 | 候选方案 | 建议顺序 | 可行性／改动规模 | 当前证据 |
|---|---|---|---|---|
| A1 | 连续移动失败后的短期绕行 | 第一批 | 高／小至中 | 同一步连续失败 27 回合 |
| A2 | 出售不可达时恢复安全采集 | 第一批 | 高／小 | 10/100 背包闲置 70 回合 |
| A3 | 任务站位、避险与截止期协调 | 第一批 | 高／中 | 第 83 回合撤离，第 84 回合任务消失 |
| A4 | 基地券提前就位与生存窗口估计 | 第二批 | 高／中 | 默认操作位不能原地给基地升级 |
| A5 | 防守工人的开火、升级、移动统一选择 | 第二批 | 高／中 | 当前夜间升级优先、炮按轮转排序 |
| B1 | 同时邻接三炮与基地的新开局阵型 | 独立实验 | 几何可行／中 | 两侧坐标复核通过，生存收益未知 |
| B2 | 以近端威胁和拥堵证据指导火箭落点 | 独立实验 | 中／中 | 当前固定后移加分与三格直击规则 |
| B3 | 采矿—出售—采购—返岗整段计划 | 第三批 | 高／中 | 矿点锁已存在，跨环节时间未统一 |
| B4 | 新闻预测证据校验与防御现金预留 | 第三批 | 高／中 | 囤矿条件未计关键券资金缺口 |

| C1 | 眩晕、修复包、炸弹应急组合 | 后续探索 | 中／中 | 官方支持，当前校验和裁判覆盖不足 |
| C2 | 动态双工人防守、混合炮种、召唤令 | 暂缓 | 不确定／中至大 | 会改变经济和动作供给，缺实战证据 |
| C3 | 长任务期间穿插新闻分析 | 暂缓 | 中／中至大 | 单模型通道存在串扰及任务延迟风险 |

“高可行性”表示所需信息和动作基本已有，**不表示收益已经验证**。优先级不等同于紧急程度评分；它综合确定性、实施成本与能否独立验证。

## 2. 先确认优化目标与规则边界

### 2.1 既有结果说明了什么

复核 v0.5 完整模拟汇总，种子 1、左右各 1300 回合：

| 换边合计 | 当前 v0.5 | 模拟器旧基线 | 差值 |
|---|---:|---:|---:|
| 任务积分 | 3100 | 4000 | -900 |
| 击杀积分 | 696 | 75 | +621 |
| 生存积分 | 1100 | 910 | +190 |
| 总分 | 4896 | 4985 | -89 |

当前策略两边基地均存活，防御收益在这组样例中确实存在；任务速度与一次任务取消抵消了这些收益。下一轮应同时看任务、现金流和防御，不能只看“存活到第十天”。

但该模拟的任务固定为 `6×7=42`，旧基线和当前策略的交互流程不同：两阶段理解会产生额外回合，而 fixture 不会奖励它在真实复杂题中的准确率价值。因此 **-900 不能直接证明两阶段流程不好，也不能承诺删掉一次模型调用就能追回这些分数**。参考 [任务 fixture](../../lab/task_fixtures.py) 第 4–21 行、[裁判任务计分](../../lab/referee.py) 第 374–380 行。

后续新方案应以本轮 `b4607e4` 为固定对照版本；与更早的 `tools/baseline_agent` 比较可保留作旁证，不能替代“新方案对当前 v0.5”的增量比较。

### 2.2 不应突破的规则

| 约束 | 来源与对方案的影响 |
|---|---|
| 同一角色每回合只能执行一个动作，一个角色只能同时操控一座武器 | [任务书](../../../../docs/任务书.md) 第 188 行；[接口文档](../../../../docs/接口文档.md) 第 217、246 行。不能让同一工人同时开三炮或开火并升级。 |
| 火箭中心 20、周边八格 10、重叠伤害叠加，发射后有 3 回合冷却空窗 | 任务书第 263 行。冷却以实际请求为准，不能承诺三炮必定每回合都有火力。 |
| 升级券需在建筑一格内使用，升级回满血 | 任务书第 300–304 行。券在背包里不等于来得及使用。 |
| 矿山采集 10 次耗尽，下一回合刷新；接口未公开矿剩余库存 | 任务书第 90–92 行。可维护估计，不能把己方采集计数当全局准确余量。 |
| 任务离开领取点周围一格、超时、死亡都会结束；完成有速度奖励，部分完成可得分 | 任务书第 384–391、457–469 行。模型还在调用不代表任务还在持续。 |
| 每日非任务 LLM 调用最多 3 次；任务期间豁免；executeCmd 仅任务期间可用 | 接口第 198、208–210 行。没有官方“每次模型调用扣金币”的依据。 |
| 合法献祭即使失败也消耗用品，宝藏只有一个 | 接口第 243 行；任务书第 427–430 行。必须先检查整套计划可执行性。 |
| 碰撞是执行失败，不等同于累计五次停调度的异常 | 任务书第 513–532 行。31 次碰撞不能写成“已触发停赛”。 |

“机器人从地图内侧袭来、前排通常低级、后排通常高级”是用户提供的实战观察；本文用于候选策略设计，但不将其升级为官方保证。机器人具体寻路和选目标细节尚不能精确重建。

## 3. 第一批：消除已有证据的空转与任务损失

### A1. 移动失败记忆与短期绕行

**已确认。** 左侧回放第 1127、1128 行起，第 564–590 回合，防守工 `10010` 从 `(18,12)` 持续争抢 `(17,13)`，对手工 `20012` 也请求该格，连续失败 27 次。另 4 次失败在 825、827、829、946 回合，原因应分别分析。该案例主要是对手争格，不能先归因于己方多人协同。

[当前寻路](../../src/agent/navigation.py) 第 25–29 行在失败后只反转搜索邻居顺序，唯一最短首步仍可能不变。

**候选方案。** 保存上次移动起点、终点及连续失败次数；第一次失败尝试另一条并列路线，同一步连续失败两次后，临时避开争用格 2–3 回合，允许安全的次短路径。到期再试，避免永久封死单格门。只对已确认失败的 `move` 建立记忆，采集或答案失败不应污染路径。

**收益与代价。** 减少交易、送券和返岗时间浪费；代价是短期绕远。独门通道无路可绕时允许等待，不能为了“有动作”走入夜间中路。

**最小验收。** 固定争格请求流与一个可绕行场景，连续相同失败动作应不再持续 27 回合；同时覆盖单格入口、对手原地驻留、镜像方向和机器人封路。增加“最大连续移动失败数、返岗迟到数”，不只看总失败次数。

### A2. 出售成为待办，不能独占整个夜晚

**已确认。** 同一回放第 1161–1299 行，第 581–650 回合，采矿工 `10012` 一直停在 `(28,8)`，背包仅 10/100 件而无自己的动作；651 回合才恢复走向小贩。这 70 回合包含黄昏警戒期及整个夜晚。

[经济策略](../../src/agent/policies/economy.py) 第 103–109 行进入出售分支后，无论 `_walk` 是否可达都会停止后续规划。中央小贩被夜间限制排除，出售状态因而反复占用决策。

**候选方案。** 保留“待出售”意图；只有成功生成移动或出售动作时才结束当前经济规划。若商路关闭、包有空间且存在可达安全侧矿，则继续采矿；满包或无安全矿时安全候售；白天恢复交易。仍保留矿点锁，不因价格每回合波动而来回切矿。

**收益与代价。** 可减少无意义等待，但不能把 70 个闲置回合全部当作必然新增产量——还需核验当时安全矿的可达性。夜间多采集也会使矿点更早耗尽并随机刷新。

**最小验收。** 夜间中央小贩、10/100 背包、存在侧矿时产生采集／前往矿点动作；包满或侧矿不可达时允许等候；天亮后正常变现。采购分支也有“路径失败仍返回已处理”的类似模式，应一起检查，但分别记录原因。

### A3. 任务站位、撤离与截止期统一考虑

**已确认。** 回放第 165 行，第 83 回合开拓者从 `(10,21)` 移至 `(9,22)`；第 167 行、第 84 回合 `phaseTask` 变空。源码 [engine](../../src/agent/engine.py) 第 34–44 行先推进任务，再对无角色动作的开拓者执行普通撤离；已有测试 [test_v05](../../tests/test_v05.py) 第 95–101 行只验证同回合存在 prompt 和 move，未验证下一回合任务是否仍有效。

**候选方案。** 接任务时绑定任务点、合法站位集合、接取回合和 `timeoutRounds`；危险时优先在任务允许范围内换位。没有安全站位且死亡风险较高时，明确选择主动放弃并记录原因。临近超时、已有可验证的部分答案时，优先提交已有成果，之后再求更好答案；不能靠编造答案换“及时提交”。

接任务前也需考虑路线、任务家族预期耗时、黄昏和站位安全。两格任务点应按实际占地计算所有合法相邻格，不能只用代表坐标判断是否安全。

**收益与代价。** 减少无意取消；过度保任务会导致死亡，所以“任务期间绝不移动”也不合适。记录并区分主动避险终止、超时、死亡与完成未知，不能把 `phaseTask` 消失当作成功证明。

**最小验收。** 必须推进后续回合检查任务仍有效；覆盖任务区内安全换位、跨界、濒死必须撤离、最后 2–3 回合、已有部分答案、两格任务点。站位选择与模型状态的关联先修正，不必同时改提示词。

## 4. 第二批：基地救命与防守工人的每回合价值

### A4. 救命券从“血量阈值”扩展为“来得及使用”

[现实现](../../src/agent/policies/defense.py) 第 60–78 行，按基地低于 100 或五格内敌人的两回合潜在伤害触发。默认 [操作位](../../src/agent/policies/construction.py) 第 14–18 行距离基地最近占地格为 2，因此正常守炮位置不能原地用基地券。

**候选方案。** 分开“提前就位”和“实际用券”：到合法使用格路线为 `L`，至少预留 `L+1` 个动作回合，再加近期堵路缓冲。用最近基地掉血、前侧墙状态、敌人攻击力和可接近方向形成生存时间区间；先走到兼顾防守的救援位置，预测来不及时才消耗券。仍保留低于 100 的紧急兜底。

需同时检查券等级、持有人存活、路径可达、是否需要暂停开火。完整官方机器人目标选择未知，不宜把“五格内敌人都连续打基地”当准确预测，也不宜因完整围墙存在就假定完全安全。

**最小验收。** 后侧 hub、远处带券、连续堵路、下一击破墙、BOSS 接近、无路、左右镜像、健康基地保券、用券与开火互斥。主要指标是“持券却来不及用”的次数和不必要的过早消耗。

### A5. 在少量合法动作中比较收益

[现防守逻辑](../../src/agent/policies/defense.py) 第 37–49 行有两个值得试验的排序：夜间持券时升级先于开火；可用炮按最久未开火优先，再看等级。

**候选方案。** 每回合只比较各就绪炮的一次攻击、合法升级、回血或移动，先保基地和操作者，再比较未来少数回合内的防御收益。无目标或全炮冷却时优先升级；不同等级炮同时可用时，结合实际有效伤害和近端威胁选择，轮转公平性只作次级条件。先做简单可解释规则，再评估是否需要 3–4 回合前瞻。

**风险。** 单回合最大伤害可能造成后续冷却空窗，或长时间不用另一座炮；高级炮有射程优势也不意味着每次都应选它。请求中的 cooldown 为事实，不根据本地推算覆盖它。

**最小验收。** 异等级炮同时就绪、近敌即将接触、升级与本回合救命射击冲突、全冷却、操作者低血。对照建筑掉血、有效伤害、可开火却空转次数和经济机会成本，严格保持一人一动作、一人一次操炮。

## 5. 有价值但应独立试验的方案

### B1. 三炮和基地共享操作位置：已确认几何可行

当前三炮的 x 坐标相同，所以“沿前线 x 坐标排序”在现阵型中不能区分三炮，实际主要由机器人距离、等级和 ID 决定。[construction](../../src/agent/policies/construction.py) 第 21–27、60–65 行。

主 Agent 计算并经防御 Agent 复核，以下新开局坐标满足：三炮位于合法武器内圈、操作格不被占用、工人同时距三炮及基地不超过一格。

| 阵营示例 | 基地锚点 | 工人操作格 | 三炮坐标 | 背侧进入格 |
|---|---|---|---|---|
| 左侧 | `(5,25)` | `(4,24)` | `(4,23)`、`(5,23)`、`(4,25)` | `(3,24)` |
| 右侧 | `(35,6)` | `(37,6)` | `(37,5)`、`(37,7)`、`(36,7)` | `(38,6)` |

基地占四格、炮占三格、工人占一格，八格互不重叠；切比雪夫距离检查均通过。这个布局有机会让防守工无需先移动即可使用基地券，也让某座炮在 x 方向更接近前线。

**尚未验证。** 真实地图空地、施工顺序、矿点和角色堵门、围墙通道、操作者存活率、火力覆盖。贴基地不等于更安全。只建议比较新开局阵型；不要为实验覆盖已经升级的炮，覆盖重建会损失已有等级投入。应在左右多个地图上比较首夜就位、被击风险、维修和经济路线。

### B2. 火箭后移由威胁证据触发

[当前落点评分](../../src/agent/policies/combat.py) 第 18–45 行限制在最近可打敌人的九宫格，后移奖励固定为 12；最近敌人距基地三格内时直击优先。

建议保持近敌优先，在候选九宫格中比较：真实可造成伤害、减少的近端攻击、后排强敌压制、前排被击杀后是否打开通道。仅在观察到前排低威胁、后排强敌与拥堵结构时考虑保留前排；基地危急、侧翼可绕行或前排已造成较大压力时退出该模式。

不能以“总溅射伤害变大”独立判优。应测试三排、斜向、侧翼绕行、低血前排、BOSS、贴墙与镜像场景，比较建筑损血和强敌接近时间。精确预测机器人移动留待官方回放支撑。

### B3. 不频繁换矿，但把整段周转纳入计划

继续遵守“近矿、采完再换、夜间两侧”的主原则。仅在新矿批次、矿点消失、满包、交易或撤离等事件重算，而不每回合重选目标。

候选估值包含到矿实际路线、可采数量估计、剩余背包、到小贩实际路线、不同矿种的出售动作数，以及到安全侧／操作位的时间。当前矿到小贩主要用直线距离，未计商路夜间关闭。[economy](../../src/agent/policies/economy.py) 第 143–153 行。

矿点耗尽后，若包内仅 10 件且旁边有近矿，可合并批次再卖；若卖掉这批即可凑够关键升级券，则提前变现更有价值。剩余矿量只能维护上下界和可信度，因为对手也可能采集。仅对少量候选进行真实路线计算，避免每回合遍历大量路线。

采购也按完整旅程计划：必要出售→商店→购买→建筑使用→返岗。身在商店且现金／背包／返岗时间均允许时，可连续两回合买好武器券与基地券再走，不必每买一张都跑一趟；不同商品仍占不同购买动作。既有样例基地券到 148/150 回合才买到，只证明时点较晚，不证明首日资金一定足够。

验证重点：近低价与远高价、仅余两格背包、矿余量不确定、夜前 3/10/20 回合、商店远近、持券者死亡、资金 99/100/199/200，记录实际变现和入夜前升级生效时间。

### B4. 新闻与现金流：分清引用、推断和观察

[新闻模块](../../src/agent/intelligence/news.py) 当前主要用模型自评置信度与非空证据接受预测；未知上涨价格有估值倍率，不能当真实未来价格。保留新闻日期、原文片段、生效／恢复时间，校验引用存在；同矿支持分阶段时间线，避免把“今天可采、明天停产、后来恢复”压成一个状态。原文引用真实也不保证语义推理正确。

实际售价优先作为当期价格证据。地图上仍有矿不必然代表可开采，停产状态应综合公告和动作反馈。预测失败应降低其权重并终止过期持有计划。

持矿前比较涨价预期与占包、停工、错过关键采购的成本。允许出售足够凑齐前线武器券或基地保命券的部分库存，余矿继续等待。防御准备充分、涨价临近且没有安全矿可采时，等待仍可能合理。

最小场景包括跨日日期换算、虚构引用、恢复公告、未来价格缺失、首夜缺券、满包等待、部分出售刚好达采购预算。指标为实际兑现收益、现金断档和关键券时点，而非模型 JSON 合格率。

### B5. SOP 与快速解题：先证明正确，再争取速度分

[任务记忆](../../src/agent/tasks/memory.py) 第 4–12 行所有记录都为 `verified=False`；[工作流](../../src/agent/tasks/workflow.py) 第 81–85 行主要使用最近几条候选，已验证 SOP 又要求完整题文哈希相同，不适合“同接口，查询北京变成上海”的参数迁移。

候选方案是按任务家族、接口／文件结构、答案格式与环境前提检索，复用步骤和验证器，不复用旧答案。分别记录探索可执行、样本已验证、平台明确成功、结束原因未知等证据等级；无法归因的任务结束不能自动升级为成功。

当前默认理解→求解两阶段。可对已有可靠验证器或已验证家族实验更短流程；探索型任务保持完整理解。deadline 应纳入模型上下文，避免临近超时仍进行大范围环境探索。命令退出码、超时、裁判错误和截断要分别处理，不把缺失输出当成功。

**暂不建议直接删除理解阶段。** 固定 42 fixture 会天然偏爱少一轮交互，应在未见任务样本中比较准确率、最高通过率、完成回合、命令失败恢复，再计算速度收益。接口未给按金币计费的模型成本，不能把调用数减少直接算作金币收入。

### B6. 宝藏第一笔支出前检查整个计划

[宝藏策略](../../src/agent/policies/treasure.py) 第 16–31 行逐件检查购买，缺少整套预算、容量和窗口结束前能否完成的统一判断。

买第一件前计算全部缺少物品的价格、空余容量、每种购买动作、真实商店与祭坛路线，以及夜间禁行等待，最后留出献祭动作。预计赶不上窗口则不继续投入；同种用品按合法 num 批量买，多个品类仍逐回合操作。与防守采购共享现金预留，防止各自看到同一笔金币就独立承诺。

多日线索的地点、时间、物品分别保留依据；条件矛盾时不只靠总体置信度放行。已花的钱记为沉没成本，不能成为继续执行失效计划的理由。验证预算差一件、容量差一格、窗口只剩几回合、夜间绕行、并发购券与重复失败计划。

## 6. 暂缓方案与讨论中的取舍

| 讨论点 | 两种观点 | 本轮建议 |
|---|---|---|
| 保任务还是立即逃离 | 任务 Agent 强调边界与部分得分；避险逻辑强调生存 | 先在任务区内换位；确需撤离时显式终止，既不无意取消，也不死守。 |
| 原矿锁定还是更高收益矿 | 持续采集减少来回移动；价格与路线变化可能带来机会 | 维持锁定原则，只在明确事件／不可达／危险时重规划，避免每回合追价。 |
| 最高伤害炮还是轮流开炮 | 单回合更高伤害有价值；冷却和后续射程也重要 | 先做少量动作比较，以防御收益为主，轮转作次级项。 |
| 保前排挡后排还是尽快击杀 | 用户观察支持堵路；侧绕、溅射和前排攻击可能抵消收益 | 有拥堵证据且基地安全时试验，不作为无条件策略。 |
| 固定两阶段还是快速回答 | 理解提高复杂任务准确率；额外交互减少速度分 | 先有未见任务样本，再按任务家族有条件精简。 |
| 把另一工人或开拓者拉回防守 | 可增加同回合操炮动作；会牺牲经济或直接结束任务 | 先优化现有防守工，必要时只研究经济工临时支援，开拓者不作默认补位。 |

C1 道具方向有官方基础：眩晕 3×3 持续 5 回合、无使用距离限制，可能为带券工人争取走位时间；修复包可维持关键墙；炸弹适合密集危险群。但有金币和动作成本，当前 [guard](../../src/agent/guard.py) 的 use 校验主要面向药剂、修复和升级，本地裁判也不完整覆盖这些效果。必须先补规则支持与独立场景，不能仅在策略里输出一个新道具命令。

C2 混合炮种、整体前移阵型、召唤令进攻会同时改变火力、角色、现金与敌群，暂不与第一批修复捆绑。研究矿山最后一次双工人同时采集虽有规则依据，但未知剩余量和协调成本使其收益不确定，优先级较低。

C3 长任务期间新闻可能积压，但插入新闻请求会占用同一个 prompt/llmResp 通道。先查真实日志是否存在严重情报延迟，再考虑显式队列；不发送两个并行 prompt，不把新闻回复当任务答案，也不为了利用额度豁免而延长任务。

## 7. 实施前应确定的验证方式

### 7.1 分开三类证据

1. **规则与协议场景**：确定性验证合法动作、单角色互斥、任务取消、反馈关联、矿点消失与夜间路径；可以在本地完成。
2. **近似对战比较**：候选与固定 v0.5 对照，在相同种子、相同对手、双方换边条件下测试；每次只启用一个核心改动，之后才测组合。固定 42 结果只说明流程与计分敏感性。
3. **真实任务／官方回放**：未见任务、真实新闻、真实模型输出和平台结果用于验证准确率和真实收益。没有此类证据时写“未验证”，不让 oracle 代替。

本轮没有新跑比赛或改测试；引用的对战数据全部来自既有 `v05-verified` 工件。几何计算只检验坐标、距离与占地，不证明阵型效果。

### 7.2 最小实验顺序

| 阶段 | 内容 | 进入下一阶段的条件 |
|---|---|---|
| E0 | 固定 v0.5、提取上述三类失败片段、补任务站位验收定义 | 复现原问题，区分合法等待、执行失败、协议异常 |
| E1 | A1、A2、A3 分别实施与分别对照 | 原失败模式改善，无非法动作、无新增任务无意取消或夜间死亡 |
| E2 | A4、A5 分别测试，再与 E1 组合 | 持券来不及用减少，防御收益提升且经济／任务损失可解释 |
| E3 | B1 新开局阵型、B2 选点、B3/B4 经济独立试验 | 多场景镜像验证，不只对一个种子调参 |
| E4 | B5 真实任务集、B6 宝藏可执行性 | 正确率／通过率不以加速为代价，资金和窗口约束满足 |

预先固定开发种子与未见验证种子，不在看到领先时临时停止。完整换边比赛为统计单位；有多个对手时分层报告。正式提升判断需要足够样本及不确定性说明，本轮不指定未经预算确认的官方比赛数量。

### 7.3 需要一起观察的指标

| 方面 | 指标 |
|---|---|
| 稳定性 | 协议异常、超时、合法动作执行失败、相同移动连续失败最大值 |
| 经济 | 有安全工作却无动作的回合数、采集／销售数量、实际金币收入、未变现库存 |
| 采购 | 首张武器券与基地券购入回合、升级生效回合、返岗迟到、重复无效采购 |
| 防御 | 基地／关键墙掉血、操作者死亡、持券却未及时用、有效伤害与攻击空窗 |
| 任务 | 意外取消、主动退出、最高通过率、完成回合、速度分、模型／命令失败恢复 |
| 宝藏与新闻 | 无收益采购金额、是否赶上窗口、重复错误献祭、预测兑现与现金断档 |
| 综合 | 换边完整结果、任务／击杀／生存分拆分、延迟分位数和最坏耗时 |

不同改动可能降低某个辅助指标却提高总收益。例如多走两步可消除长期争格，减少囤矿利润可能换来首夜升级。应解释这种取舍，不把所有指标都要求单调提升。
