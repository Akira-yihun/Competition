# v0.7 角色目标、阵型、采集与沙盒任务实施记录

日期：2026-09-19。状态：先记录方案，现已完成实现与本地验证；未上传平台。全部写入限于 CoreGeek/ChatGPT。

## 本轮需求与策略

1. 日志保持 ROUND、req、rsp 和分项正文，新增 submitAnswer，取消重复 diagnostics；本地模拟生成相同可读日志。
2. 建设采用用户指定的左右镜像阵型：左基地锚点 (x,y)，操作格 (x-1,y-1)，火箭炮 (x-1,y)、(x-1,y-2)、(x,y-2)；右侧操作格 (x+2,y)，火箭炮 (x+2,y-1)、(x+2,y+1)、(x+1,y+1)。同格可操作三炮和升级基地。
3. “+”为优先墙：正面六格，以及上下边靠前四格（角点去重，共十二格）。“@”为次要后侧墙，施工始终保留后侧进出通道。
4. 防御工负责建炮、采石、优先墙、购券及夜守；经济工从第一回合独立采贵矿，开拓者从第一回合向任务点行动。每个角色保存职责、目标、阶段、开始回合、打断原因及等待理由。
5. 选矿先限定本阵营附近区域，并限制相对基地和工人的绕行，再计算单位价格×预计批量／到矿回合、采集回合、基地距离和售卖距离的加权成本。目标锁定，除耗尽、停采、危险、长期不可达或更高优先级工作外不更换；夜间优先己方基地背侧可达矿。
6. 防御工按采集→集中售卖／采购→回基地修建升级→夜守的阶段行动。保留首批三炮预算，武器券优先，基地券保留救命，墙券与关键墙修复后续安排；避免每拿到一张券就单独长途返程。夜前用真实回程、施工和用券动作估计截止时刻，预留余量，最晚第70回合就位；第71回合不因普通升级占掉开火机会。
7. 经济工夜间商人不可达时继续采安全矿，不让出售待办阻塞采集。包未满可合并矿批；关键升级资金需要时允许提前销售。
8. 开拓者保持任务点目标；接取后绑定允许站位和截止期。机器人全局可见，普通任务行动不受固定中路禁行约束；只依据临近机器人及可能一步攻击范围避险，先在任务范围内换位，无法保命才主动离开。
9. 沙盒环境初始完全未知。提示词明确未知工作目录、文档路径、目录结构和 API 用法；通过 executeCmd 探索，不猜路径。保存本任务的命令及对应结果、已验证事实、错误和待办，所有后续模型请求都收到完整任务和累积交互记录（超长内容明确截断）。
10. 模型每轮只选择 executeCmd 或 taskAnswer。答案严格按题目格式；最终答案同时携带任务家族、参数化步骤和验证方法摘要，作为后续同任务点任务的候选 SOP，不直接复制旧答案、不把任务消失当确定成功。

## 代码组织计划

- policies/construction.py：布局和墙优先级。
- policies/mining.py：本地矿候选、性价比、目标锁定和采售决策。
- policies/economy.py：防御工工作阶段、施工与采购调度；保留既有兼容入口。
- policies/pioneer.py：任务点选择、任务站位和避险。
- objectives.py：角色目标状态、动作及等待理由、移动失败记忆。
- navigation.py：通用路径与短期争格绕行，允许任务角色使用独立危险约束。
- tasks/workflow.py、memory.py、channel.py：沙盒回合证据、命令与答案协议、任务点经验复用。
- engine.py：只负责角色策略顺序、共享预留与最终校验。

## 实施顺序与验收

先调整布局与目标状态，再实现采售／防御阶段，随后任务站位和沙盒交互，最后日志与本地验证。保留用户之前采完再换、前线升级、救命基地券及近敌火箭策略。

重点场景：第一回合三角色有明确动作、左右阵型距离、矿点不跨角且不频繁变动、夜间背矿继续采集、出售不可达、堵路绕行、日落准时就位、首夜可开火、任务区内躲避／必要放弃、同任务点换城市复用步骤、文档未知路径、API 多次错误恢复、日志 submitAnswer 与无 diagnostics。

本地结果仅为近似裁判和确定性模型样本，不能冒充真实 API 调用或官方解题正确率。若地图无可达资源或持续被对手堵住，不能保证完成全部建设；优先保证安全和回防，并记录未完成原因。

## 实现与回归中修正的问题

- 已按计划拆分采矿、开拓者、角色目标及沙盒提示词／证据模块；入口 main3.py 保持原样。三个角色使用独立职责和持久状态的策略代理，动作由共享调度器协调，不额外为两个工人消耗 LLM 调用。
- 回程估算发现自身旧位置被当成障碍：推演矿点返程时，仍留在基地的工人占位使操作格“不可达”，防御工因而提前转入回家阶段。路径阻挡现在按角色身份排除自身，已有采石耗尽后建墙回归覆盖此问题。
- 防御工的固定操作格预留原先也阻挡了自己的经济阶段移动，现按角色释放／重设预留；任务点2的两格占地现统一用于任务接取、持续站位与最终动作校验。
- 安全移动或用药占用开拓者动作时，模型答案先保存，下一回合提交，避免丢失刚返回的命令／答案结果。
- HTTP 回归原先可能打新包却解压旧包，现明确构建并测试同一个 v0.7 包。

## 沙盒任务流程样本

[沙盒逐轮日志](../../artifacts/v07-sandbox/rounds.log)模拟北京→南京→成都的连续任务：先定位文件、读取说明，旧调用失败后查询帮助并修正；北京使用6次命令，后两题分别复用参数化步骤执行1次命令；在21、56、91回合提交本题 JSON 答案。3个任务的命令／结果进入后续 prompt，任务摘要以 submitted_unconfirmed 保存，不把提交或任务结束冒充官方确认。

此样本不执行真实 shell、网络或真实大模型调用，仅证明多回合证据传递、错误恢复与经验复用的数据通路。全量证据太长时会分级截断并明确标记；原始返回仍可在 req 日志查看。机器人避险目前用附近威胁及合法站位评估，不宣称精确预测官方机器人完整路径。
