# 游戏目标、策略与当前代码审计

日期：2026-09-17。依据：`docs/任务书.md`、`接口文档.md`（均 v1.0，2026-09-09），以及当前 `CoreGeek/src/agent/` 源码；未采用其他模型的结论。源码基线 HEAD：`e8dc40893232b0a82295c47c1a5ad018b44be7b4`，用户已有未提交修改不纳入本次修改范围。本文是静态规则与代码分析及少量本地复现，不声称已完成平台对战验证。源码定位相对于 `CoreGeek/ChatGPT/`，行号是撰写时的快照。

## 1. 先明确真正的优化目标

**事实：**一局有交换位置的两个半场，每半场最多 1300 回合（10 天）；白天 70、黑夜 60。赢一局积 3 分、平局 1 分、败局 0 分。优化主指标应为固定评测分布上的官方整局积分均值 `3 × P(win) + P(draw)`，辅以胜率、失败率及最差地图表现，不能把单次半场分数作为最终目标。

任务书第七章给出的半场规则：

| 状态 | 文档结论 | 评测处理 |
|---|---|---|
| 双方基地先后在不同回合被毁 | 先被毁者负 | 记录双方毁灭回合，不用高积分覆盖失败 |
| 双方同回合被毁 | 积分高者胜，同分平 | 官方分数为准 |
| 双方均存活至结束 | 积分高者胜 | 任务和击杀分决定差距 |
| 恰有一方基地被毁 | 未以独立条款明确写全 | 向平台确认；不得将自行推定的结果当官方胜负 |
| 异常累计导致停调度或双方异常终止 | 给出停调度/结束条件，但未单列最终判定 | 保存官方结果及异常字段，不用本地猜测 |

**事实：**两个半场同一方均胜，该方整局胜；各胜一场比较两场分数之和，同分平局。**待确认：**含半场平局的整局组合、只有一方存活、终止异常的完整判定矩阵。评测适配器应优先读取官方整局结果；缺失时标为 `unresolved`，不可计入有效胜率。

**策略推断：**形成“服务稳定 → 控制基地毁灭风险 → 在安全裕度内提高得分 → 按对手调整进攻投入”的层次。生存并非唯一目标：双方都活满时，过量围墙和未花金币不能直接增加得分；反之，只刷任务导致基地更早被毁，也可能直接失败。

## 2. 积分与经济的量级

- 完整任务：`任务奖励 + 5 × timeoutRounds / (完成回合 - 接取回合)`。时间奖励意味着任务提速有实际价值；零回合分母的处理未写明，不应设计依赖该边界的策略。
- 部分任务：`任务奖励 × 通过率`；金币同样按通过率给付。提交过的最佳通过率在超时结算时有效，因此应优先提交有证据的部分答案，再继续完善。
- 机器人：小/中/大/BOSS 每个分别 1/2/4/10 分，血量 40/60/500/800，攻击力 5/10/20/40，攻击距离均为 3。击杀价值与存活威胁不是同一排序。
- 生存：`Σ 10 × day × 存活系数`，存活到全部 10 天合计 550 分；被毁当天及以后没有当天生存分。
- 初始金币 75，单塔 25，武器总上限 **3 座**，不是每类各 3 座。花完初始金币不是必然最优：需要验证三塔建设速度、操炮人数及升级机会成本。
- 武器/基地升级到 2、3 级分别需要 100、150 金币；升级恢复满血，因此是增容与修复的联合决策。不能把最高血量增长简单当作唯一收益。
- 白天建造限制适用于工人的武器/围墙；购买、售卖、使用、采集、任务等动作并未统一规定“只能白天”，夜晚能否安全开展应按动作规则判断。

## 3. 地图与单位约束对策略的影响

**事实：**地图 41×32，八方向移动和切比雪夫距离；基地 `pos` 是 2×2 占地的左上角，因此占用 `(x,y)、(x+1,y)、(x,y-1)、(x+1,y-1)`。角色、建筑、中立区域、矿区、机器人阻挡移动，对角夹缝允许通过。基地外一圈是武器区域，再外一圈是围墙区域。

**事实：**机器人全图可见，并给出 `targetTeam`；敌方基地/围墙全图可见，其他敌方单位有共享半径 4 的视野限制。敌方角色不在观测里不等于死亡，不得据此计算确定敌军数量或己方击杀。

**策略推断：**

1. 建造布局同时优化射程覆盖、人员站位和出入口；角色必须在塔周围一格操炮，三座塔不意味着必有三座塔同时输出。围墙完工前验证基地内外可达和操炮位可达。
2. 依据路径长度和剩余昼间回合决定返防，不能到入夜才让远处工人回家。用“预计到位回合 ≤ 夜晚首轮威胁到达回合 - 安全余量”定义召回阈值。
3. 为 3 名角色做最小代价匹配（枚举仅 6 种排列），维护同回合目标格预留，识别拥堵后重规划。角色死亡后重新分配。
4. 所有相对方位以己方基地和地图中心建立坐标系；固定按 x 排序的布局需要单独验证换边公平性。
5. 机器人寻路、集火和目标挑选算法在文档中不完整。围墙诱导、堵门聚怪只能作为待实验假设，不能假设已知底层仇恨机制。

## 4. 候选策略组合

### 4.1 安全经济与升级

工人目标函数可先用 `预期售出收入 / (去矿路径 + 采集回合 + 去小贩路径 + 售卖回合)`，同时扣除返防迟到、围墙石头储备和危险地区代价。`vendorShopList` 是当前价格的结构化依据，新闻用于预测后续供给/价格变化。矿区会枯竭刷新，禁止永久缓存路径目标。

共享金币采用每回合预算预留：两个工人的可支付能力不能都读取同一个未扣减余额。升级计划至少比较基地升级、主塔升级、必要围墙、应急物品四项；储备应急费或升级券能降低尾部失败，但其最优规模须对战验证。

### 4.2 任务与自进化

采用持久任务状态机：`选择任务 → 到位 → 领取确认 → 理解 → executeCmd 探索 → 读取 lastCmdResult → 提交部分/完整答案 → 读取错误与任务变化 → 总结可复用 SOP → 下一任务`。把任务文本、命令输出和模型结果当输入数据，严格关联任务实例，不能把上个任务的 `llmResp` 当作本任务答案。

任务选择应考虑“预期积分 + 金币战略价值 + 后续 SOP 收益”除以“走路 + 解题 + 刷新等待”，加入超时和返防风险；不能直接把金币和积分 1:1 相加。每次领取后任务点附近站位需要保持；离开一格范围、死亡、超时、完成均结束任务，之后刷新等待 30 回合。

普通阶段每游戏日可调用 LLM 3 次，任务期间不受该限制且不计入额度；`executeCmd` 仅任务期间有效，沙盒无外网、每条最多 15 秒，结果下一回合回传。运行中的比赛代理通过平台异步接口做任务，离线开发 CLI 负责修改程序，两者职责不同。夜晚让开拓者操炮还是继续任务应由边际防御收益决定，而非无条件切换。

### 4.3 战斗微操

- 加特林：每弹 10，等级决定目标数；任意两个落点相对塔的方向夹角必须 ≤90°。使用整数点积非负检测所有目标对（零向量另行排除），不要用含坐标轴的“象限”近似替代。
- 电磁炮：等级 1/2/3 总能量为 10/20/30，按沿途机器人当前血量依次消耗；并非对每只穿透机器人都造成完整攻击力。选择弹道时考虑前方目标截获能量。
- 火箭：中心 20、周围 8 格 10，等级决定导弹数量，重复落点伤害可叠加；发射后有 3 回合冷却空窗。不要未经确认把周期平均伤害按每 3 回合一次计算。
- 联合选靶应优先防止即将造成基地/操炮者死亡的威胁，再考虑击杀积分及总有效伤害；同回合伤害在回合末统一结算，跨塔分配预期伤害以避免严重溢出。武器攻击在机器人移动之前，使用当前位置估算落点，不能简单射击其下一格。
- 火箭枚举合法落点的 3×3 影响，而非仅枚举机器人中心；可命中更多机器人或减少过杀。溅射区域应包括射程外一格内受波及机器人，而落点自身必须合法。
- 区分攻击我方与攻击对方的机器人；帮助对手消灭机器人可能有积分收益但也改善其生存，不应默认无差别开火。击杀归属和对方目标机器人的积分归属须先确认。

优先评测“一塔各一种”基线与双火箭、双加特林等配置，搭配相同预算和升级节奏；不在无对战证据时宣布某一塔型全局最强。

### 4.4 宝藏与主动施压

保存跨日民间传闻及证据，解析地点、时间、物品集合，结合商店实际商品准备。合法 `summonTreasure` 即使失败也消耗用品，不能无限盲探；结果 2 区分不了地点错误与尚未开启，3 说明用品集合错误，4 说明宝藏已空。全图一个宝藏、同回合正确双方都得奖励，带来竞速收益。

召唤令是次夜施压工具，每天至多 10 张。先保证自身生存及任务投入，再实验针对对手薄弱防御的召唤；这也可能给对手增加击杀分。三级火箭全图射程是否能有效直接攻击敌方基地及其伤害细则，应按平台补充规则/回放确认，不把概述中的“可进攻对手”直接等价成所有武器对所有单位均有同样伤害。

## 6. 推荐实验顺序与通过条件

每次只检验一个核心假设，具体打包、平台操作和统计见 `02-Loop工程计划.md`。以下是研发优先序，不表示已实现：

1. 建立合法输入回放、请求边界、stdout 无敏感明文、确定性响应和打包启动检查；以官方异常次数为硬指标。
2. 修正加特林、共享预算、动作反馈、观测缺失；对关键边界做最小合成场景，确保不会提升异常或无效动作率。
3. 夜前召回与角色匹配：检验首夜空窗、操作员死亡率、基地受伤、成对整局积分。
4. 任务执行状态机：检验任务完成率/耗时/金币、跨昼夜中止次数；与无沙盒基线对照。
5. 基地/武器升级与经济：先证明资源收入能转为安全或得分，再优化采矿批量、卖矿路线和新闻处理。
6. 炮型/布局/联合选靶：固定其他策略，按地图与对手分层，保留失败回放。
7. 宝藏、自进化知识复用、主动召唤：独立消融，防止以更多模型调用或特定地图记忆冒充通用收益。

主指标是独立对局单位的官方整局结果；半场、回合、同一 seed 的重复对局不应当作完全独立样本夸大置信度。辅助指标包括协议异常、动作失败、基地死亡回合、任务完成率、金币获取/花费、操炮空窗、有效伤害估计、角色死亡与拥堵。前后状态差只能提供推断，不能把“机器人消失”直接写成己方击杀（晨间会自动清除、对方也可攻击）。

## 7. 平台确认清单

确认完整胜负矩阵与官方结果字段；地图/seed/任务集如何固定；每次平台“对战”是否已经包含换边；回合从 0 还是 1 起；武器弹道障碍与对敌建筑/角色伤害细则；重复加特林落点；击杀积分归属；机器人目标/移动机制；死亡单位是否保留；任务点2的两格表示及领取距离；升级/物品是否允许夜间使用；火箭冷却准确恢复时序；日志接口范围和大小/截断限制。未知项记录为待确认或实验假设，不能在实现里藏成已知常量。
