# 本地实验室的证据边界

先读 [工程交接](../AGENT.md) 和 [测试命令](../tests/AGENT.md)。实验室是近似裁判，不是官方平台。

- referee.py、rules.py模拟地图、动作和计分；evaluate.py运行固定种子和换边对比，输出每边请求／响应／反馈、摘要、源码哈希及可读日志。
- 默认reasoning是确定性模型样本，不是真实LLM。tools模式只验证工具交互机制，不用于双方能力比较；sandbox_scenario.py同样不实际执行shell或网络。
- replay.py用于回放；intelligence_scenario.py验证新闻相关流程；task_fixtures.py定义合成任务。对手固定在tools/baseline_agent，不能跟着候选修改。

地图生成、机器人波次与路径、任务内容和延迟、部分战斗细节均有本地假设；PvP、真实API等缺口见summary.limitations。裁判不支持的动作不能静默判成功。

修改裁判必须引用官方规则并补独立测试，不根据候选的预期倒推规则。裁判修改后旧结果与新结果不能直接混比；同时重跑基线和候选。代码执行中不要热改源码。

分析优先查：基地是否存活、每夜第一回合操作者就位、墙／塔建设升级、工人死亡与复活、采集和售卖、动作失败、任务接取／提交时延、得分分项、最大和p95耗时。只有总分或收集动作次数不足以证明优化。

历史最终结果是artifacts/v07-final-matches，旧v07-matches包含修复前缺墙失败。不要删除旧实验掩盖回归。工件被忽略或未带到新机器时，按测试命令再生成，并标上新的版本和时间。
